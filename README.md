# Лабораторна робота №3 — варіант 6
## Робота з файлами, логування та обробка виключень

**Максимальна оцінка — 10 балів.**

### 🎯 Що ви навчитеся робити

Відрізняти помилку в коді від поганих вхідних даних, читати дані з файлу так, щоб один зіпсований рядок не зупиняв програму, і залишати в лозі слід того, що відбувалося.

---

### 📦 Де працюєте

Репозиторій той самий — домен і варіант теж. Профіль вашого варіанта: **[Доменні профілі](https://github.com/Java-Univer-2025/Java-Univer-2025.github.io/blob/main/lab-01/tasks_2025_domains.md)**.

Після того як PR ЛР2 змерджено:

```
git checkout main
git pull
git checkout -b lab3
```

Здаєте через pull request `lab3` → `main`, захист — по діффу у вашому PR.

Компактні конструктори з ЛР2 **не змінюються** і кидають unchecked `IllegalArgumentException`, а нове виключення має бути checked.

### 📋 Що зробити

**1. Створіть checked-виключення `InvalidDataException`** з двома конструкторами: з повідомленням і з повідомленням та причиною (`cause`).

**2. Підготуйте CSV-файл** з даними для класів, які не посилаються на інші сутності, і покладіть його в `data/` у корені репозиторію:

```
roomNumber,type,pricePerNight
101,SINGLE,850.0
102,DELUXE,2400.0
```

Перший рядок — заголовок. Розділювач — кома, без лапок; дробові числа через крапку; кодування UTF-8.

Щонайменше три рядки мають бути некоректними, і кожен — по-своєму.

**3. Напишіть читання файла.** Некоректний рядок перетворюється на `InvalidDataException` з номером рядка в повідомленні, пропускається — і читання триває. Відсутній файл програму не зупиняє.

Використайте `try-with-resources`, `finally` і `multi-catch` — кожен там, де він справді потрібен.

**4. Додайте логування через SLF4J:**

```groovy
dependencies {
    implementation 'org.slf4j:slf4j-api:<версія>'
    runtimeOnly    'ch.qos.logback:logback-classic:<версія>'
}
```

```java
private static final Logger log = LoggerFactory.getLogger(RoomLoader.class);

log.info("Loaded {} rooms", rooms.size());
```

Задійте три рівні — `INFO`, `WARN`, `ERROR` — кожен для своїх подій.

**5. Напишіть тести** на JUnit 5, щонайменше шість:

- коректне створення обʼєктів;
- `InvalidDataException` на некоректних рядках;
- логіка обчислюваних методів.

Тести не повинні залежати від файла в `data/`.

**6. Оновіть `Main`.** Показати треба:

1. читання файла з коректними й некоректними рядками;
2. спробу прочитати відсутній файл;
3. некоректне значення в сеттері змінюваного класу і його обробку;
4. логування всіх трьох рівнів.

### ✍️ Оформлення

Коментарі, javadoc, `@DisplayName` і тексти виключень — англійською. Українською — тільки те, що бачить користувач: рядки виводу в `Main`.

### 🤖 Частина про AI

5–7 речень:
- чим користувалися і що просили — ключовий промпт наведіть дослівно;
- **що AI зробив неправильно або не так, як вимагає завдання**, і як ви це помітили;
- що виправили самі й чому.

Якщо не користувалися — покажіть AI одне своє рішення і опишіть, з чим у його відповіді погоджуєтесь, з чим ні й чому.

### 🎤 Захист

5 хвилин, 3–4 питання по **вашому** коду й по діффу у вашому PR. Орієнтовно:

- Чому `InvalidDataException` checked, а конструктор record-а кидає unchecked?
- Що передаєте як `cause` і що зникне зі стектрейсу без нього?
- Скільки різних виключень ловить ваш `catch` при розборі рядка — і чому саме стільки?
- Чим `try-with-resources` відрізняється від закриття файла у `finally`?
- Яке виключення кидає відсутній файл у вашому коді — і чи було б воно тим самим, якби ви відкривали файл інакше?
- Чому в лозі пишуть `"Loaded {} rooms"`, а не `"Loaded " + n + " rooms"`? Як у лог потрапляє стектрейс?
- Що перевіряє ваш тест на некоректний рядок — і чи впаде він, якщо парсер почне пропускати такі рядки мовчки?
